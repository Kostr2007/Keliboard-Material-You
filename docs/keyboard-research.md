# Исследование клавиатур: что взять в KeliBoard Material You

Октябрь 2026. Изучены FlorisBoard, HeliBoard (база KeliBoard), сам KeliBoard и Gboard
как ориентир по UX. Gboard изучался только по поведению и публичным материалам:
его код и ресурсы закрыты, поэтому ничего из них не переносится.

## Лицензии

| Источник | Код | Что можно использовать |
|---|---|---|
| KeliBoard / HeliBoard / OpenBoard | GPL-3.0 (+ Apache-2.0 от AOSP) | всё, с сохранением уведомлений |
| FlorisBoard | Apache-2.0 | идеи и код можно включать в GPL-3.0 проект (обратное неверно) |
| AOSP LatinIME | Apache-2.0 | основа текущего движка |
| Jetpack Compose / Material 3 | Apache-2.0 | параметры motion tokens (жёсткость, затухание) — это просто числа из спецификации |
| Gboard | проприетарный | только наблюдаемое поведение, без кода, ресурсов, иконок |
| Шрифт Google Sans | проприетарный | не включаем, используем системный шрифт |
| Emoji Kitchen, стикеры, GIF | ресурсы Google / сетевые сервисы | не включаем |
| Библиотека glide typing | закрытая, поставляется пользователем | без изменений (уже так в HeliBoard) |
| Словари HeliBoard | разные (в т.ч. CC-BY-SA, Apache) | уже поставляются, новые не добавляем |

## Как устроено сейчас (KeliBoard)

- Клавиатура — это классический `View` (`KeyboardView`/`MainKeyboardView`), клавиши рисуются
  на `Canvas`. Compose используется только в настройках, поэтому анимации клавиатуры
  нужно делать средствами `View`, а не `animate*AsState`.
- Нажатие: `PointerTracker` → `DrawingProxy.onKeyPressed/onKeyReleased` →
  `Key.onPressed()` + `invalidateKey()`. Фон меняется мгновенно через `StateListDrawable`
  (`state_pressed`). Ввод символа не зависит от отрисовки, это важно сохранить.
- Предпросмотр клавиши (`KeyPreviewChoreographer`) показывается и прячется без анимации.
- Панель вариантов по долгому нажатию (`PopupKeysKeyboardView`) появляется мгновенно.
- Панель подсказок (`SuggestionStripView`) пересоздаёт подписи при каждом наборе символа.
- Динамические цвета есть (`DynamicColors`, Android 12+), но тона подобраны вручную
  и не соответствуют ролям Material 3 (например, светлая клавиша Enter с белым значком).
- По умолчанию — стиль Material без рамок клавиш и светлая тема, а не Material You.

## Что нашлось у других

- **FlorisBoard** (Compose): состояние нажатия — это селектор темы (Snygg `PRESSED`),
  без пружин; анимирован только угасающий след жеста (`ValueAnimator`).
  Всплывающие варианты — отдельный `PopupUiController`. Подсказки и проверка
  орфографии в релизах пока отсутствуют.
- **HeliBoard**: та же архитектура, что у нас; жесты по пробелу и Backspace, панель
  инструментов, история буфера, поиск эмодзи — всё это в KeliBoard уже есть.
- **Gboard** (наблюдаемое поведение): клавиши Material You (Enter — цвет primary,
  служебные клавиши — secondary container), мягкий отклик нажатия, появление
  предпросмотра и вариантов с лёгким «пружинным» масштабом, без задержки ввода.

## Сознательно отклонено

- **Перенос клавиатуры на Compose** — переписывание работающего движка ввода без
  технической необходимости, высокий риск регрессий и падения производительности.
- **Голосовой ввод, перевод, GIF, стикеры, Emoji Kitchen** — требуют сети или
  проприетарных ресурсов; KeliBoard принципиально работает офлайн.
- **Рукописный ввод, нейросетевые подсказки и «проверка текста» (proofread)** —
  нужны модели на десятки мегабайт и инфраструктура обновления. Реалистичный
  вариант на будущее — подключаемая модель, как сейчас подключается библиотека жестов.
- **Автоматическая вибрация на анимации** — вибрация остаётся только по
  существующим настройкам пользователя.
- **Жест по Backspace, курсор по пробелу, буфер обмена, поиск эмодзи** — уже есть.
